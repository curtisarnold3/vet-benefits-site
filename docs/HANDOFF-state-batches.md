## Curt's non-negotiable rules

1. Official sources only: the state veterans affairs agency, department of revenue or taxation, DMV, wildlife and parks agency, higher-education agency, state personnel site, county assessor .gov pages, and the state's statutes or constitution. No blogs, law firms, VSO summaries, or news as the source.
2. Never invent a benefit or threshold. If you believe a benefit exists but cannot find an official source, include it with `needs_verification: true` and say what could not be confirmed.
3. Quote the exact threshold language from the source in the narrative. Note how the state treats 100% schedular vs 100% P&T vs TDIU. Note residency rules, surviving-spouse rules, filing deadlines and which office, and county or town variation (`varies_by_county: true`).
4. Plain language, about 8th grade reading level, 2 to 4 sentences per `details`.
5. Check for 2025 and 2026 law changes; many states changed property tax rules recently.
6. Today's date goes in `date_verified` and `last_verified` (YYYY-MM-DD).

## JSON schema (exact)

```json
{
  "code": "XX", "name": "State Name", "slug": "state-name",
  "agency": {"name": "official state veterans agency", "url": "https://..."},
  "last_verified": "YYYY-MM-DD", "status": "verified",
  "notes": ["5 to 12 plain-language eligibility traps"],
  "benefits": [
    {
      "benefit": "short name",
      "category": "property_tax | vehicle | recreation | education | income_tax | employment | other",
      "min_rating": "none | any service-connected | 10% | 30% | 50% | 60% | 70% | 100% | 100% P&T or TDIU | 100% P&T | varies",
      "details": "2 to 4 plain sentences: what you get, who qualifies (exact threshold), how and where to apply, deadline",
      "source_url": "full official URL",
      "source_title": "page or statute title",
      "date_verified": "YYYY-MM-DD",
      "needs_verification": false,
      "varies_by_county": false
    }
  ]
}
```

`min_rating` must be one of the listed strings. If the real threshold is a number not in the list (for example 40%), use `"varies"` and put the real number in `details`. 8 to 15 benefit rows per state.

## How a batch runs (what worked for batches 2 and 3)

1. Create a scratch folder (for example `/tmp/batchN/`). Write the research brief below to `BRIEF.md` there.
2. Spawn one research subagent per state, all in parallel, each told: "Read BRIEF.md and follow it exactly for STATE (code XX, slug xx). Hints to verify: ... Save the narrative to `/tmp/batchN/XX.md` and the JSON alone to `/tmp/batchN/XX.json` before replying." Each takes 15 to 22 minutes and 150k to 250k tokens. They often exhaust their web-search budget near the end; that is expected, and they fall back to direct fetches.
3. As each lands: `node scripts/merge-state.js /tmp/batchN/XX.json`. Fix anything it rejects (usually an enum typo or a `min_rating` like "40%").
4. After all ten: `node scripts/make-state-pages.js`, then `node -e "JSON.parse(require('fs').readFileSync('data/states.json'))"`.
5. Curl every `source_url` for the batch. A 404 must be fixed (find the moved page or point at the agency root and set `needs_verification: true`). A 403 or timeout is usually a bot block; open it in a browser to confirm it loads, then leave it.
6. Copy the ten `XX.md` files to `docs/research/states-batch-N/` and write `README.md` there: per state, the sources used and the needs-verification items (the batch-3 README is the template; a small Python script that reads `states.json` can generate most of it).
7. Preview one page: `npx serve . -l 4173` then open `http://localhost:4173/states/<slug>.html`. The table should show rows, filters, notes.
8. Commit on `main`: `States batch N: XX, XX, ... verified; research notes` and push. Confirm the GitHub Actions run is green (`gh run list --limit 1`) and `https://claimbasecamp.com/data/states.json` shows the new states as verified.
9. Final message to Curt: per-state sources list and the needs-verification list, so he can spot-check.
